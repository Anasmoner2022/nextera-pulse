1. EXECUTIVE OVERVIEW & PROBLEM STATEMENT
--------------------------------------------------------------------------------
Nextera Pulse is an operational Student Success and Learning Intelligence system
built to monitor student progress in 01Edu/01NextEra. 01Edu holds the raw learning
data (levels, XP, progress, audits, checkpoints, status records), but lacks the
operational intelligence to tell mentors:
  (1) Who is on track?
  (2) Who is drifting or falling behind?
  (3) What is the exact reason?
  (4) What intervention should be taken?

The North Star Metric for the project is the "On-Track Rate" (% of students at
or above the configured minimum level for their active curriculum month).

Sprint 1's goal is "Trust Pace": Prove that for the pilot cohort (Cohort 4,
Event 97, 52 students), the system can accurately and deterministically compute
active curriculum days, curriculum month, target levels, gap calculations, and
pace status (GREEN / YELLOW / RED / PAUSED / ONBOARDING), and expose this to
Ziad's React frontend via a clean REST API.

4. LOCKED BUSINESS RULES & PACE ENGINE FORMULAS
--------------------------------------------------------------------------------
(A) Clock Anchor:
    The student's academic clock starts at event_user.createdAt (the joinedAt
    column in the roster). event.endAt is NEVER used for pacing.

(B) Status Policy (status_policy table):
    +------------------+-------------+-------------------------+
    | Record Type      | Pause Clock | Exclude from Active KPI |
    +------------------+-------------+-------------------------+
    | away             | false       | false                   |
    | restricted       | true        | true                    |
    | blocked-long     | true        | true                    |
    | temporary-notice | false       | false                   |
    | left-school      | true (term) | true                    |
    | observation      | false       | false                   |
    | ban              | true        | true                    |
    +------------------+-------------+-------------------------+

(C) Active Program Days & Curriculum Month:
    pause_days = SUM(overlap_days(status_interval, enrolled_at .. now))
                 WHERE status_policy.pause_clock = true
    active_program_days = MAX(0, FLOOR(now - enrolled_at) - pause_days)
    curriculum_month = FLOOR(active_program_days / 30) + 1

(D) Official Event 97 Curriculum Timeline (curriculum_timeline table):
    Month  2:  Min 5.0,   Expected  7.0,  Checkpoint 0
    Month  4:  Min 9.0,   Expected 13.0,  Checkpoint 0
    Month  5:  Min 12.0,  Expected 17.0,  Checkpoint 10
    Month  6:  Min 15.0,  Expected 18.0,  Checkpoint 20
    Month  7:  Min 17.0,  Expected 20.0,  Checkpoint 20
    Month  8:  Min 20.0,  Expected 23.0,  Checkpoint 30
    Month 10:  Min 28.0,  Expected 34.0,  Checkpoint 30
    Month 12:  Min 34.0,  Expected 38.0,  Checkpoint 40
    Month 18:  Min 50.0,  Expected 62.0,  Checkpoint 50

(E) Deterministic Status Evaluation:
    - If left_school: state = INACTIVE
    - Else if currently_paused: state = PAUSED (Reason: ADMINISTRATIVE_PAUSE)
    - Else if curriculum_month == 1: state = ONBOARDING (first 30 days)
    - Else if actual_level >= expected_level: state = GREEN
    - Else if actual_level >= min_level: state = YELLOW (Reason: PACE_BELOW_TARGET)
    - Else (actual_level < min_level): state = RED (Reason: PACE_BELOW_MINIMUM)

(F) Gaps:
    gap_to_minimum  = actual_level - target.min_level
    gap_to_expected = actual_level - target.expected_level

6. TECHNICAL PITFALLS & ISSUES RESOLVED (THE "FAILED" PARTS)
--------------------------------------------------------------------------------
Be aware of these 6 critical issues that were encountered and resolved during
implementation so CODEX does not re-introduce them:

(1) UTF-8 Byte Order Mark (BOM) in CSV Files:
    - Problem: Cohort-4-Roster.csv starts with \xef\xbb\xbf.
    - Error: Go's encoding/csv threw 'parse error on line 1, column 4: bare " in non-quoted-field'.
    - Fix: Added bytes.TrimPrefix(content, []byte("\xef\xbb\xbf")) before feeding
      into csv.NewReader.

(2) "Infinity" Values in JSON Serialization:
    - Problem: Student Mina Fayeq (ID 636) has auditRatio = "Infinity" in 01Edu.
    - Error: strconv.ParseFloat parsed this into float64(+Inf). In Go,
      encoding/json returns 'json: unsupported value: +Inf'. When writeJSON was
      called, w.WriteHeader(200) was sent first, but json.Encode failed mid-stream,
      resulting in an empty 0-byte HTTP response body.
    - Fix: Added math.IsInf(val, 0) and math.IsNaN(val) guards, clamping invalid
      ratios to 0.0. Also changed writeJSON to buffer-serialize first.

(3) PostgreSQL Boolean vs. Integer Type Strictness:
    - Problem: In SQLite, boolean flags can be queried as is_primary = 1.
    - Error: PostgreSQL strictly requires booleans; threw 'operator does not exist:
      boolean = integer (42883)'.
    - Fix: Changed all queries to 'm.is_primary = TRUE' and passed Go boolean true.

(4) Mentor Assignment Duplication on Re-seed:
    - Problem: Running seed.exe twice inserted duplicate mentor rows because
      mentor_assignments lacked a unique constraint on (student_id, is_primary).
      This caused the LEFT JOIN to duplicate students (52 * 2 = 104 rows).
    - Fix: Added 'DELETE FROM mentor_assignments;' in the seeder before populating.

(5) DateTime Deserialization Across Drivers:
    - Problem: SQLite driver stored time.Time using Go's String() representation
      ('2025-11-23 08:36:14.28417 +0000 +0000'), causing time.Parse(time.RFC3339)
      to fail and evaluate enrolled_at to 0001-01-01 (resulting in 106,751 active days).
    - Fix: Created internal/store/time.go with ParseFlexibleTime() and FormatTime()
      to strictly enforce UTC RFC3339 strings across both databases.

(6) WSL2 PostgreSQL Networking & Idle Sleep Behavior:
    - Problem A: localhost resolved to IPv6 [::1]:5432, which was actively refused.
    - Problem B: When no interactive process is running in WSL2, Windows unloads
      the WSL VM, causing PostgreSQL to trigger a shutdown (57P03).
    - Fix: Explicitly bound PostgreSQL to 0.0.0.0:5432 in postgresql.conf and
      added 'host all all all trust' in pg_hba.conf. For local development on
      Windows, keep a background session running or run PostgreSQL via Docker.
